Yaadein — Database Schema Reference

Event photo & video sharing platform — Postgres / Supabase. Anonymous guest uploads, post-expiry face grouping.

Core guest flow (no login) Guest scans QR → app generates a guest_session_id client-side → first time that session is seen, a row is created in guests → if face search is enabled, guest sees a consent checkbox + optional name (writes to face_consents) → guest uploads media (media.guest_session_id set, no users row created) → after events.storage_expires_at, a batch job clusters faces into face_clusters.

users core

Only people who actually log in — hosts, photographers, admins. Guests never get a row here; they're identified by a client-generated session ID instead.

DDL
CREATE TABLE users (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  phone           text UNIQUE NOT NULL,
  name            text,
  role            text CHECK (role IN ('host','photographer','admin')),
  auth_provider   text,
  created_at      timestamptz DEFAULT now()
);

events core

The tenant boundary. Almost every other table scopes itself to one event — this is the single most important foreign key in the schema.

DDL
CREATE TABLE events (
  id                   uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  host_id              uuid REFERENCES users(id),
  slug                 text UNIQUE NOT NULL,
  face_search_enabled  boolean DEFAULT false,
  plan                 text CHECK (plan IN ('basic','premium','professional')),
  storage_expires_at   timestamptz,
  is_wedding           boolean DEFAULT false,
  created_at           timestamptz DEFAULT now()
);

guests core

One row per anonymous attendee, keyed off their client-generated guest_session_id. Created the first time that session is seen (consent screen or first upload, whichever comes first). Gives analytics, repeat-visit tracking, and a single place to store a guest's self-typed name/phone instead of duplicating it across face_consents and face_clusters.

DDL
CREATE TABLE guests (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id          uuid NOT NULL REFERENCES events(id),
  guest_session_id  uuid NOT NULL,
  name              text,
  phone             text,
  first_seen_at     timestamptz DEFAULT now(),
  last_seen_at      timestamptz DEFAULT now(),
  UNIQUE (event_id, guest_session_id)
);

Still no login, no password, no auth token — this row exists purely so a session ID isn't scattered raw across three other tables. face_consents.guest_session_id and media.guest_session_id now both resolve back to this table for name/phone lookups.
media core

One row per uploaded photo/video. Partitioned by event_id since ~95% of queries are event-scoped. Either uploaded_by (logged-in host/photographer) or guest_session_id (anonymous guest) is set — never both. Metadata columns support duplicate detection, download-size estimation, and video processing — all explicit v1 requirements in the steering doc.

DDL
CREATE TABLE media (
  id                 uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id           uuid NOT NULL REFERENCES events(id),
  uploaded_by        uuid REFERENCES users(id),
  guest_session_id   uuid,
  type               text CHECK (type IN ('image','video')),
  r2_object_key      text NOT NULL,
  idempotency_key    text NOT NULL,
  status             text CHECK (status IN ('pending_verify','scanning','processing','visible','rejected')),
  file_size_bytes    bigint,
  mime_type          text,
  checksum           text,
  width              int,
  height             int,
  duration_seconds   int,
  thumbnail_url      text,
  created_at         timestamptz DEFAULT now(),
  UNIQUE (event_id, idempotency_key),
  CHECK (uploaded_by IS NOT NULL OR guest_session_id IS NOT NULL)
) PARTITION BY HASH (event_id);

payments core

Transaction and upgrade audit trail. upgrade_trigger records why a payment happened (e.g. overage), not just the amount — needed for the overage policy where uploads never get hard-blocked.

DDL
CREATE TABLE payments (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         uuid REFERENCES users(id),
  event_id        uuid REFERENCES events(id),
  plan            text,
  amount          numeric,
  status          text CHECK (status IN ('pending','success','failed','refunded')),
  upgrade_trigger text,
  created_at      timestamptz DEFAULT now()
);

face_consents face recognition

The compliance anchor for DPDP Act biometric rules. Tied to guest_session_id, not a user account, so consent can be proven even for guests who never log in — and survives the embedding's eventual purge.

DDL
CREATE TABLE face_consents (
  id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id            uuid NOT NULL REFERENCES events(id),
  guest_session_id    uuid NOT NULL,
  guest_name          text,
  consent_given_at    timestamptz NOT NULL,
  consent_revoked_at  timestamptz,
  purge_executed_at   timestamptz
);

face_clusters face recognition

One row per distinct person detected within an event, created by the post-expiry batch clustering job. matched_guest_session_id is only set if the cluster turns out to be a consenting guest's own self-tagged face.

DDL
CREATE TABLE face_clusters (
  id                        uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id                  uuid NOT NULL REFERENCES events(id),
  matched_guest_session_id  uuid,
  matched_guest_name        text,
  cover_thumbnail_url       text
);

face_embeddings face recognition

One row per detected face per photo. cluster_id stays null until the batch job runs post-expiry. pgvector-indexed and scoped by event_id so similarity search can never cross events. uploader_consent_id records that the uploader's session consented to face search on this photo — it does not claim that every face detected in the photo belongs to a consenting person. A single image can contain many faces from only one consenting uploader.

DDL
CREATE TABLE face_embeddings (
  id                   uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id             uuid NOT NULL REFERENCES events(id),
  media_id             uuid REFERENCES media(id),
  embedding            vector(512),
  cluster_id           uuid REFERENCES face_clusters(id),
  uploader_consent_id  uuid NOT NULL REFERENCES face_consents(id),
  purge_at             timestamptz NOT NULL,
  created_at           timestamptz DEFAULT now()
);

CREATE INDEX ON face_embeddings USING hnsw (embedding vector_cosine_ops);
CREATE INDEX ON face_embeddings (event_id, cluster_id);

gallery_cache supporting

Offloads hot-event gallery reads from Postgres. Refreshed on write, not read — a "hot wedding" shouldn't hammer the primary database on every page load.

DDL
CREATE TABLE gallery_cache (
  event_id        uuid PRIMARY KEY REFERENCES events(id),
  cached_payload  jsonb,
  refreshed_at    timestamptz
);

exports supporting

Lifecycle tracking for async ZIP/album download jobs — exports are Celery jobs, not media rows.

DDL
CREATE TABLE exports (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id      uuid NOT NULL REFERENCES events(id),
  requested_by  uuid REFERENCES users(id),
  scope         text CHECK (scope IN ('single','album','full_event')),
  status        text CHECK (status IN ('queued','processing','ready','failed')),
  download_url  text
);
